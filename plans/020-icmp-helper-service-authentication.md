## Why this matters

`hiddify-core/v2/hcore/icmpservice/` is an elevated helper process (launched
on demand via `HiddifyCli.exe icmp run`, triggering a Windows UAC "runas"
prompt — see `icmp_platform_service.go:61-64`'s own doc comment and
`admin_service_commander.go:88-98`, `launchHelper`) that exposes a gRPC
server on `127.0.0.1:18021` with the same shape of problem as the Tunnel
helper (plan 019): **zero authentication**.

`icmp_platform_service.go:65-87` (`StartIcmpService`):

```go
func StartIcmpService() (int, string) {
	watcher := newIdleWatcher()
	svc := NewIcmpService(watcher.onSessionCountChanged)

	addr := fmt.Sprintf("127.0.0.1:%d", icmpServicePort)
	lis, err := net.Listen("tcp", addr)
	if err != nil {
		return 1, fmt.Sprintf("failed to listen on %s: %v", addr, err)
	}

	server := grpc.NewServer()
	RegisterIcmpServiceServer(server, svc)
	// ... server.Serve(lis) in a goroutine, no credentials, no interceptor
```

`icmp_service.go:53-75` (`OpenSession`) lets any caller open a real raw ICMP
socket (`icmp.ListenPacket`) on the machine, `ReadFrom`/`WriteTo`
(`:83-122`) relay arbitrary bytes to/from any caller-supplied destination
IP, and `Exit` (`:160-163`) unconditionally shuts the elevated helper down
for anyone who calls it — the legitimate caller,
`admin_service_commander.go:74-86,130-141` (`pingHelper`, `ExitIcmpHelper`)
and `remote_conn.go:42-58` (`DialRemoteICMP`), all dial with
`grpc.WithInsecure()`, confirming there's no existing auth mechanism to
preserve. Net effect: any unprivileged local process can obtain raw ICMP
socket access it could not otherwise get without elevation, and can DoS the
helper via the unauthenticated `Exit`.

## Current state

Files this plan touches:

- `hiddify-core/v2/hcore/icmpservice/icmp_platform_service.go` — starts the

- `hiddify-core/v2/hcore/icmpservice/admin_service_commander.go` — the
  legitimate in-process callers: `pingHelper` (`:74-86`), `launchHelper`
  (`:88-98`), `ExitIcmpHelper` (`:129-141`), all using `icmpServiceAddress`
  (`:20`).
- `hiddify-core/v2/hcore/icmpservice/remote_conn.go` — `DialRemoteICMP`
  (`:27-58`), the other real client of this service.

The shared token helper this plan reuses (added by plan 019, reproduced here
so this plan is self-contained even if read alone):

```go
// hiddify-core/v2/hutils/service_token.go
package hutils

func GenerateAndPersistServiceToken(dir, name string) (string, error) // writes "<name>.token", 0o600
func ReadServiceToken(dir, name string) (string, error)               // reads it back
```

Unlike the Tunnel service (a persistent OS service that can start at boot
before the app runs), the ICMP helper is launched fresh by `launchHelper()`
every time it's needed and self-exits after `idleTimeout` (8 minutes,
`icmp_platform_service.go:24`) with no open sessions — but it can still
outlive the process that launched it (the main app could restart while the
helper is mid-idle-timeout), so this plan uses the same **file-based** token
(generated by the helper itself when it starts, read by any caller from the
same file) rather than passing a token only in-memory via the launch
command — an in-memory-only token would break reconnection from a fresh
app instance while the previously-launched helper is still alive.

### Step 2: Generate the token on startup and check it via an interceptor

In `icmp_platform_service.go`, generate the token inside `StartIcmpService`
before starting the listener:

```go
func StartIcmpService() (int, string) {
	watcher := newIdleWatcher()
	svc := NewIcmpService(watcher.onSessionCountChanged)

	dir, err := executableDir() // per Step 1
	if err != nil {
		return 1, fmt.Sprintf("failed to resolve executable directory: %v", err)
	}
	token, err := hutils.GenerateAndPersistServiceToken(dir, "icmp")
	if err != nil {
		return 1, fmt.Sprintf("failed to generate auth token: %v", err)
	}

	addr := fmt.Sprintf("127.0.0.1:%d", icmpServicePort)
	lis, err := net.Listen("tcp", addr)
	if err != nil {
		return 1, fmt.Sprintf("failed to listen on %s: %v", addr, err)
	}

	server := grpc.NewServer(grpc.ChainUnaryInterceptor(tokenAuthInterceptor(token)))
	RegisterIcmpServiceServer(server, svc)
	// ... unchanged below
```

Add `tokenAuthInterceptor` in this package (same shape as plan 019's — a
small, duplicated ~8-line function is fine here rather than sharing it
across two otherwise-unrelated packages just to avoid repeating it):

```go
func tokenAuthInterceptor(expected string) grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (interface{}, error) {
		md, ok := metadata.FromIncomingContext(ctx)
		if !ok || subtle.ConstantTimeCompare([]byte(strings.Join(md.Get("token"), "")), []byte(expected)) != 1 {
			return nil, status.Error(codes.Unauthenticated, "missing or invalid token")
		}
		return handler(ctx, req)
	}
}
```

Add the needed imports (`context`, `crypto/subtle`, `strings`,
`google.golang.org/grpc/metadata`, `google.golang.org/grpc/codes`,
`google.golang.org/grpc/status`, `github.com/hiddify/hiddify-core/v2/hutils`).

**Verify**: `cd hiddify-core && go build ./v2/hcore/icmpservice/...` → exit 0.

### Step 3: Have every client read and send the token

In `admin_service_commander.go`, add a small helper mirroring plan 019's
`dialTunnelService` (adjust names for this service):

```go
func dialIcmpService() (*grpc.ClientConn, context.Context, context.CancelFunc, error) {
	dir, err := executableDir()
	if err != nil {
		return nil, nil, nil, err
	}
	token, err := hutils.ReadServiceToken(dir, "icmp")
	if err != nil {
		return nil, nil, nil, fmt.Errorf("read icmp service token: %w", err)
	}
	conn, err := grpc.Dial(icmpServiceAddress, grpc.WithInsecure())
	if err != nil {
		return nil, nil, nil, err
	}
	ctx := metadata.AppendToOutgoingContext(context.Background(), "token", token)
	return conn, ctx, nil, nil
}
```

Update `pingHelper` and `ExitIcmpHelper` (both in this file) and
`DialRemoteICMP` (in `remote_conn.go`) to use this helper instead of their
current bare `grpc.Dial(icmpServiceAddress, grpc.WithInsecure())` +
`context.Background()`, preserving each call site's existing per-call
timeout (wrap the returned context in `context.WithTimeout` with the same
durations already used: 2s for `pingHelper`, 2s for `ExitIcmpHelper`, 5s for
`DialRemoteICMP`'s `OpenSession` call).

**If reading the token fails because the helper hasn't started yet** (e.g.
`pingHelper` is called specifically to check whether the helper is running,
before it necessarily exists) — that's an expected, valid outcome: treat a
missing token file the same as any other "helper not reachable" condition
(return the read error up, which `EnsureIcmpHelperRunning` already handles by
falling through to `launchHelper()`). Don't change that control flow's
overall shape, just make the dial-and-call path token-aware.

**Verify**: `cd hiddify-core && go build ./v2/hcore/icmpservice/...` → exit 0.
`grep -c "ReadServiceToken" v2/hcore/icmpservice/admin_service_commander.go`
returns at least `1`, and `grep -c "ReadServiceToken" v2/hcore/icmpservice/remote_conn.go`
returns at least `1`.
